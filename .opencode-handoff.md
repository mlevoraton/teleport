# Teleport OSS White-Label and SSO — Handoff

## Objective

Continue the Teleport v15.5.4 OSS fork as the independent `WarpNavigator` project, with safe white-label branding and an accurate GitHub SSO experience while staying inside capabilities actually present in OSS.

## Current Phase

Phases 1 (branding), 2 (GitHub connector UX/config example), and 3 (public WarpNavigator identity defaults) are implemented and verified, including real local proxy/browser smoke tests. Phase 4 (clean-room Enterprise-to-OSS capability audit) is underway; Access List web UI scaffold, service layer, and feature registration are complete and under review. Login Rule remains excluded.

## Constraints and Decisions

- `proxy_service.ui.branding` in `teleport.yaml` is the single branding source.
- Branding asset URLs must be root-relative same-origin paths; external URLs are rejected so the existing CSP remains unchanged.
- No arbitrary CSS injection or `window.__BRANDING__`/`window.__THEMES__` runtime globals.
- Custom themes use the compiled frontend allowlist only (`bblp` currently exists).
- The Helm chart can pass `teleport.yaml` through `proxy.teleportConfig`, but it does not serve branding assets. A same-origin ingress/reverse proxy must expose paths such as `/branding/logo.svg`.
- Authentication/session semantics were not changed; login changes are presentation-only.
- Do not add Enterprise-only Login Rule or Access List UI without implementing and authorizing the corresponding OSS server APIs.
- `WarpNavigator` is the public identity. The Go module, `teleport`/`tctl`/`tsh` binaries, APIs, resource kinds, config keys, images, and Helm interfaces remain compatible legacy names until separately migrated and tested.
- Preserve upstream copyrights and license notices. Public documentation must describe WarpNavigator as an independent derivative, not an official Gravitational product.
